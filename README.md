**Enforced session journal for Claude Code / Claude Desktop.** Captures what `/compact` wipes — your preferences, vocabulary, decisions, rejected options, debugging hypotheses, the rules you taught Claude. v3 stores everything in **one central place** and keeps itself alive with **hooks**: the journal is read into every session automatically, a turn can't end while today's entry is stale, and retired storage paths are write-protected. No more "remember to run /bro".

## Install (60 seconds)

```bash
curl -fsSL https://raw.githubusercontent.com/balaka/bro/main/scripts/bro-install.sh | bash
```

Open a new session inside a git repository and just work — bro recognizes it and connects itself once you've had a few exchanges there (a handful of responses, configurable; see **Setup** in [SKILL.md](./SKILL.md)). Not a git repository, or want it connected right now under a name of your choosing? Type `/bro setup`. Done either way — from then on the hooks do the remembering.

Upgrading from v1/v2? Same command, then `/bro migrate` when the session-start hook flags your old logs. See [MIGRATION.md](./MIGRATION.md) — nothing is ever deleted.

Already on v3? Same command again (or `/bro update`): it re-registers the hooks, and that is the whole upgrade — no data migration inside v3. Reopen the chats that were open during the update.

## Why v3 exists

v2 had two structural failures, reported by real daily use:

1. **A folder per chat.** Parallel chats didn't know about each other; per-chat summaries went stale; principles accumulated in per-repo copies that drifted apart. After a few months: 16 storage folders across the disk, 14 of them dead, and no way to answer "where is my stuff?"
2. **Discipline instead of enforcement.** bro worked only while the model remembered to call it. Models forget — reliably. A rule without an enforcer is a wish.

v3 answers both:

- **One store.** `~/bro/` — global principles (one copy), one folder per project, one `INDEX.md` registry over everything. The unit is **project + day**, not chat: every chat of the day writes sections into the same daily file. Nothing to synchronize.
- **Hooks as enforcers.** The harness — not the model's memory — injects the read-order at session start, blocks the end of a turn while today's journal is stale, and denies writes to legacy paths so an old chat can't clobber the migrated store.

## Layout

```
~/bro/
  INDEX.md            registry: one line per workspace — files, last entry
  _principles.md      global principles (working discipline, privacy, people) — the only copy
  _state.md           operator-state snapshot — ONE for the whole store, newest wins
  _rule-candidates.md   RULE: markers queue — enters principles only on operator confirmation
  cowork/
    _workspace.md     what this is + people (thin)
    decisions.md      decision register — harvested from DECIDED: markers, ADR-style chains
    open.md           open-items register — harvested from TAIL: markers, closed by a CLOSED:/ЗАКРЫТ: marker, never by hand
    vocab.md          vocabulary register — harvested from TERM: markers
    insights.md       insight register — harvested from INSIGHT: markers, last 10 shown every session
    2026-09-06.md     daily journal — all chats of the day, in anchored sections
    _legacy-v2/       preserved v2 thread summaries
  _archive/           migrated v1/v2 storages, byte-for-byte
```

Journal entries use eight markers, English or Russian. The original six accept RU in either ALL CAPS or Capitalized writing: `DECIDED:` / `REJECTED:` / `RULE:` / `TAIL:` / `TERM:` / `CLOSED:` (`РЕШЕНИЕ:`/`Решение:`, `ОТКАЗ:`/`Отказ:`, `ПРАВИЛО:`/`Правило:`, `ХВОСТ:`/`Хвост:`, `ТЕРМИН:`/`Термин:`, `ЗАКРЫТ:`/`Закрыт:`). The two newer ones, `STATE:` and `INSIGHT:` (`СОСТОЯНИЕ:`/`ИНСАЙТ:`), accept ALL CAPS only in either language — a real-journal check found the Capitalized RU writing is mostly an old habit of captioning test/branch/build status, not the operator's own state, so accepting it would let an ordinary caption silently overwrite a real snapshot. A near-miss that still doesn't parse (wrong grammatical form, lowercase, a dash instead of a colon) is never silently dropped: it's counted and logged once per pass to `~/.claude/bro/health.log`. Markers are seeds: the **harvest script** (run by the session-start hook, and — since 3.8 — again in the background after every answer) moves them into the registers with stable ids — a tail written once cannot be lost, it sits in `open.md` until closed with its own `CLOSED:`/`ЗАКРЫТ:` marker (never a hand-edit — see **Appending** below). `STATE:`/`СОСТОЯНИЕ:` is the one exception to "into a register": it replaces a single store-wide snapshot instead of accumulating — see **Operator state and insights** below. Operator-confirmed rules move up to `_principles.md`; nothing enters principles without the operator's word. Operator's verbatim words are never translated or trimmed. `INDEX.md` is generated by harvest — a view, never hand-edited. The journal itself is only ever appended to through `bro-append.sh` — see **Appending** below.

## Appending — `bro-append.sh` (the sole write path)

A daily journal is shared by every chat in a workspace, so as of v3.7 no chat Writes/Edits it directly any more — `bro-append.sh` is the only way in: it stamps `HH:MM`/date from the real clock (an invented section time can't be typed, there's no time argument), rejects a malformed body before a byte is written, auto-inserts the blank line after a marker so nothing glues to the next paragraph, appends under a lock, and logs the line range + a sha256 of it to `<ws>/.append-log` so the stop hook's lint can trust it later. Since 3.8 it also rejects a `TAIL:`/`ХВОСТ:` line that packs several items (two or more `; `-separated clauses, a numbered list, or over ~400 characters) before writing anything — one open item per line, split the rest into their own `TAIL:` lines. The write guard (below) denies a direct Write/Edit, or a Bash command whose write TARGET resolves to the journal, and points here instead.

## Operator state and insights

Two new markers capture what used to fall through the cracks between sessions:

- **`STATE:`/`СОСТОЯНИЕ:`** — how the operator is doing and what mode the work is in right now (tired, irritated, energized, what length of answer they'll tolerate). One side of the snapshot per line; every `STATE:` line in one journal section is a side of the SAME snapshot. Kept store-wide in `~/bro/_state.md` — one file, not per workspace — and only the newest snapshot survives (by when it was written, never by read order, so re-harvesting old journals can't regress it). Shown first in every session's opening text, even before a workspace has resolved (it belongs to the whole store, not one project), tagged with its age in hours.
- **`INSIGHT:`/`ИНСАЙТ:`** — a pattern, idea or new approach worth not losing: bold the conclusion, then 1–4 sentences, one line. Accumulates in `<ws>/insights.md` like `vocab.md`; the last 10 for the workspace, by their own birth date (not file position — harvest only ever appends, so a `--full` re-read can't quietly turn an old insight into the "newest" one), open every session, the rest are found by search.

## The hooks

| Hook | Event | What it guarantees |
|---|---|---|
| `bro-session-start.sh` | SessionStart (startup / resume / compact / clear) | Read-order injected into every session, leading with the operator-state snapshot (even before a workspace resolves) and ending with the last 10 insights (by birth date); storage-version mismatch flagged → `/bro migrate`. Since 3.8: recognizes an unconnected git repository (worktrees, submodules and linked copies collapsed to the one real project; exclusions apply — `$HOME`, `~/Desktop`, `~/Downloads`, inside the store itself) but does not create the workspace — it hints how many responses until it self-connects (see the turnstile row below); outside a git repository, or when the repo's name can't be slugged, hints `/bro setup` instead. Every `git` call is capped at ~2s. Does nothing slow, so it cannot time out |
| `bro-harvest-hook.sh` | SessionStart, and (since 3.8) Stop — both async | Markers harvested into the registers in the background, only what is new since the last pass — now also after every answer, not just at session start. A per-workspace, non-blocking lock skips a trigger outright if that workspace's harvest is already running, instead of queueing behind it |
| `bro-precompact.sh` | PreCompact | Marks the session as "start owed" before every compaction, so the watchdog checks the re-injection instead of assuming it |
| `bro-stop-turnstile.sh` | Stop (shares its group with `bro-harvest-hook.sh` above) | Since 3.8, also the other half of self-create: counts a pending chat's own responses (deduped by prompt) against `autoCreateAfterAnswers`; silent below threshold. At it, checking whether the folder is still missing and creating it happen together under one lock keyed to that project's path — if two chats cross the threshold together, only the one that actually finds it missing and creates it is blocked to start the chronicle; the other finds it already there and falls through to the ordinary flow. Otherwise: a turn can't end while today's journal is missing or stale (default 30 min; configurable), or fails lint outside anything `bro-append.sh` already validated (a hand-edit or pre-3.7 content still gets full scrutiny — the trust is hash-gated, not session-based). Blocks at most once per prompt — can't loop. Watchdog: a session start that never finished is recovered here and reported, never silent |
| `bro-write-guard.sh` | PreToolUse (Write\|Edit\|Bash) | Writes to retired v2 paths denied, redirected to the central store; a direct Write/Edit, or a Bash command whose write TARGET resolves to a shared daily journal (redirect — spaced or glued to the target — `tee`, `sed`/`perl -i`, `cp`/`install`/`ln`, `dd of=`, `truncate`, `rm`/`unlink`, `mv` checking both source and destination, or a python/node write call), is denied too, redirected to `bro-append.sh`. Since 3.8 it scans for the write target rather than the journal's path merely appearing in the command text: a quoted heredoc body is dropped outright; an unquoted one is buffered whole and, if `$(` or a backtick appears anywhere in it, the WHOLE body is scanned as command text — the same treatment every heredoc got before this fix; with neither, it's dropped entirely. A heredoc fed to a nested interpreter is never dropped either way, since it genuinely executes. Recognizes `$HOME/…`/`${HOME}/…` alongside `~/…`, and resolves a relative target against the command's own `cd`/`pushd` history, including inside a `( cd DIR; … )` subshell; once a `cd` argument is a variable or `cd -`, the directory becomes unknowable for the rest of the command, and a relative target is then blocked only if its own name is already journal-shaped (`YYYY-MM-DD*.md`). Known gaps, honestly: an operator glued to the word BEFORE it too, a target's own path built from a shell variable or earlier substitution, and a `cp`/`sed -i` destination expressed via a flag placed after the path all go unseen — a narrow, best-effort nudge, not the safety net (the stop hook's hash-gated lint is) |

Config: `~/.claude/bro-config.json` — `root` (store location), `staleMinutes` (turnstile threshold), `autoCreateAfterAnswers` (responses before a recognized git repo becomes a workspace, default 5), `workspaces` (path→name overrides).

## Commands

- `/bro` — capture now (classify since last entry: journal / workspace summary / principles-candidate)
- `/bro status` — freshness table for all workspaces, hook state, conflicts
- `/bro setup` — enable bro for the current project
- `/bro off` / `/bro on` — switch bro off/on for the current chat only (project stays enabled; the write guard stays on)
- `/bro harvest` — manual harvest over all workspaces (the session-start hook harvests the current one automatically)
- `/bro migrate` — deterministic migration of v1/v2 storages ([MIGRATION.md](./MIGRATION.md))
- `/bro update` — pull latest + reinstall (idempotent)

## Migration guarantees (v1/v2 → v3)

Migration is a **script** (`scripts/bro-migrate.sh`), not model improvisation — same input, same output, any machine:

- tar.gz backup first; originals archived wholesale to `~/bro/_archive/`; pointer file left behind
- daily logs byte-for-byte; same-date threads merged under explicit `## (thread: …)` headers
- v2 thread summaries kept verbatim; principles concatenated with provenance
- duplicate headings listed in `CONFLICTS.md` for a human to resolve — the script never decides which rule wins
- idempotent; `--dry-run` prints the plan and changes nothing
