**Enforced session journal for Claude Code / Claude Desktop.** Captures what `/compact` wipes — your preferences, vocabulary, decisions, rejected options, debugging hypotheses, the rules you taught Claude. v3 stores everything in **one central place** and keeps itself alive with **hooks**: the journal is read into every session automatically, a turn can't end while today's entry is stale, and retired storage paths are write-protected. No more "remember to run /bro".

## Install (60 seconds)

```bash
curl -fsSL https://raw.githubusercontent.com/balaka/bro/main/scripts/bro-install.sh | bash
```

Open a new session, `cd` your project, type `/bro setup` once per project. Done — from then on the hooks do the remembering.

Upgrading from v1/v2? Same command, then `/bro migrate` when the session-start hook flags your old logs. See [MIGRATION.md](./MIGRATION.md) — nothing is ever deleted.

Already on v3? Same command again (or `/bro update`): it re-registers the hooks, and that is the whole upgrade — no data migration inside v3. Reopen the chats that were open during the update.

---

## Why v3 exists

v2 had two structural failures, reported by real daily use:

1. **A folder per chat.** Parallel chats didn't know about each other; per-chat summaries went stale; principles accumulated in per-repo copies that drifted apart. After a few months: 16 storage folders across the disk, 14 of them dead, and no way to answer "where is my stuff?"
2. **Discipline instead of enforcement.** bro worked only while the model remembered to call it. Models forget — reliably. A rule without an enforcer is a wish.

v3 answers both:

- **One store.** `~/bro/` — global principles (one copy), one folder per project, one `INDEX.md` registry over everything. The unit is **project + day**, not chat: every chat of the day writes sections into the same daily file. Nothing to synchronize.
- **Hooks as enforcers.** The harness — not the model's memory — injects the read-order at session start, blocks the end of a turn while today's journal is stale, and denies writes to legacy paths so an old chat can't clobber the migrated store.

## Layout

```
~/bro/
  INDEX.md            registry: one line per workspace — files, last entry
  _principles.md      global principles (working discipline, privacy, people) — the only copy
  _rule-candidates.md   RULE: markers queue — enters principles only on operator confirmation
  cowork/
    _workspace.md     what this is + people (thin)
    decisions.md      decision register — harvested from DECIDED: markers, ADR-style chains
    open.md           open-items register — harvested from TAIL: markers, closed by a CLOSED:/ЗАКРЫТ: marker, never by hand
    vocab.md          vocabulary register — harvested from TERM: markers
    2026-09-06.md     daily journal — all chats of the day, in anchored sections
    _legacy-v2/       preserved v2 thread summaries
  _archive/           migrated v1/v2 storages, byte-for-byte
```

Journal entries use six markers, English or Russian: `DECIDED:` / `REJECTED:` / `RULE:` / `TAIL:` / `TERM:` / `CLOSED:` (`РЕШЕНИЕ:` / `ОТКАЗ:` / `ПРАВИЛО:` / `ХВОСТ:` / `ТЕРМИН:` / `ЗАКРЫТ:`). Markers are seeds: the **harvest script** (run by the session-start hook) moves them into the registers with stable ids — a tail written once cannot be lost, it sits in `open.md` until closed with its own `CLOSED:`/`ЗАКРЫТ:` marker (never a hand-edit — see **Appending** below). Operator-confirmed rules move up to `_principles.md`; nothing enters principles without the operator's word. Operator's verbatim words are never translated or trimmed. `INDEX.md` is generated by harvest — a view, never hand-edited. The journal itself is only ever appended to through `bro-append.sh` — see **Appending** below.

## Appending — `bro-append.sh` (the sole write path)

A daily journal is shared by every chat in a workspace, so as of v3.7 no chat Writes/Edits it directly any more — `bro-append.sh` is the only way in: it stamps `HH:MM`/date from the real clock (an invented section time can't be typed, there's no time argument), rejects a malformed body before a byte is written, auto-inserts the blank line after a marker so nothing glues to the next paragraph, appends under a lock, and logs the line range + a sha256 of it to `<ws>/.append-log` so the stop hook's lint can trust it later. The write guard (below) denies a direct Write/Edit or an obvious Bash redirect into the journal and points here instead.

## The hooks

| Hook | Event | What it guarantees |
|---|---|---|
| `bro-session-start.sh` | SessionStart (startup / resume / compact / clear) | Read-order injected into every session; storage-version mismatch flagged → `/bro migrate`. Does nothing slow, so it cannot time out |
| `bro-harvest-hook.sh` | SessionStart, async | Markers harvested into the registers in the background, only what is new since the last pass |
| `bro-precompact.sh` | PreCompact | Marks the session as "start owed" before every compaction, so the watchdog checks the re-injection instead of assuming it |
| `bro-stop-turnstile.sh` | Stop | A turn can't end while today's journal is missing or stale (default 30 min; configurable), or fails lint outside anything `bro-append.sh` already validated (a hand-edit or pre-3.7 content still gets full scrutiny — the trust is hash-gated, not session-based). Blocks at most once per prompt — can't loop. Watchdog: a session start that never finished is recovered here and reported, never silent |
| `bro-write-guard.sh` | PreToolUse (Write\|Edit\|Bash) | Writes to retired v2 paths denied, redirected to the central store; a direct Write/Edit or an obvious Bash redirect/`tee`/`sed -i` into a shared daily journal is denied too, redirected to `bro-append.sh` |

Config: `~/.claude/bro-config.json` — `root` (store location), `staleMinutes` (turnstile threshold), `workspaces` (path→name overrides).

## Commands

- `/bro` — capture now (classify since last entry: journal / workspace summary / principles-candidate)
- `/bro status` — freshness table for all workspaces, hook state, conflicts
- `/bro setup` — enable bro for the current project
- `/bro off` / `/bro on` — switch bro off/on for the current chat only (project stays enabled; the write guard stays on)
- `/bro harvest` — manual harvest over all workspaces (the session-start hook harvests the current one automatically)
- `/bro migrate` — deterministic migration of v1/v2 storages ([MIGRATION.md](./MIGRATION.md))
- `/bro update` — pull latest + reinstall (idempotent)

## Migration guarantees (v1/v2 → v3)

Migration is a **script** (`scripts/bro-migrate.sh`), not model improvisation — same input, same output, any machine:

- tar.gz backup first; originals archived wholesale to `~/bro/_archive/`; pointer file left behind
- daily logs byte-for-byte; same-date threads merged under explicit `## (thread: …)` headers
- v2 thread summaries kept verbatim; principles concatenated with provenance
- duplicate headings listed in `CONFLICTS.md` for a human to resolve — the script never decides which rule wins
- idempotent; `--dry-run` prints the plan and changes nothing

## Changelog

- **3.7.0** — tails get a real close, the journal gets a real write path. Two structural gaps closed: (1) closing a `TAIL:`/`ХВОСТ:` item meant hand-editing `open.md` directly — the one register mutation in the codebase with no lock and no script; a sixth marker, `CLOSED:`/`ЗАКРЫТ:`, closes a tail through harvest instead (names the tail's own id; a bad or missing one is a CLOSE-MISS, logged and surfaced every session, never silently dropped). (2) every parallel chat wrote its own section into the shared daily journal with raw Write/Edit — one chat's malformed header or invented (non-clock) timestamp blocked every other chat's turn until fixed by hand; `bro-append.sh` is now the only way to add a section (stamps `HH:MM`/date from the real clock — no time argument exists, so an invented time can't be typed; validates the body before a byte is written; appends atomically under a lock; logs what it wrote for the stop hook to trust later). The write guard denies a direct Write/Edit or an obvious Bash redirect/`tee`/`sed -i` into the journal and points to the script instead; the stop hook's format lint is now hash-gated — a range `bro-append.sh` already validated is skipped, a hand-edit or pre-3.7 content still gets full scrutiny. Also fixed: a marker's harvested body used to swallow the next paragraph when the writer forgot a blank line — harvest now takes only the marker's own physical line (ids are computed the same way as before, so nothing already harvested is duplicated on a `--full` re-read of an unedited journal; editing text that used to glue onto an already-harvested marker can still file a second record under a new id — a known limitation, documented in `bro-harvest.sh`'s own header, not fixed in this release). New shared `scripts/bro-lib.sh` (`lock()`/`unlock()`, `hash_range()`, the one canonical marker regex) replaces three drifting copies with one. Upgrade = re-run the installer; a chat already open when it runs keeps writing the journal directly with Edit/Write until it's reopened, at which point the guard redirects it to `bro-append.sh`. Not in this release: the backlog watchdog that nudges a bulk tail cleanup, the rule-review queue becoming a real block, the read-tracker, the completeness check — staged for a later release.
- **3.6.0** — session start can no longer die silently. Harvest used to run inside the session-start hook, before the context was emitted; once a workspace grew past two weeks of busy journals (30 s of harvest against a 10 s hook timeout) the harness cancelled the hook and discarded its output — every new, resumed or compacted chat started without principles and read-order, registers stopped filling, and nothing said so. Now: the session-start hook only injects context (0.6 s on the same workspace); harvest runs as its own `async` hook and is incremental (only journals changed since the last completed pass, only the lines added since; `--full` re-reads everything); the stop hook watches the start hook (and a PreCompact hook re-arms that watch before every compaction) — a start that never finished is recovered at the end of the first turn, logged to `~/.claude/bro/health.log`, and the operator is told; the same stop hook checks that a harvest pass completed after the session started, and has the chat run it when the background hook is not there (chats opened before the update). Upgrade = re-run the installer (`/bro update`); no data migration; reopen chats that were open
